### MAJOR

**M-1: AC09 lock-in does NOT verify Condition 11's `post-cap page length ≤ MAX_CONSISTENCY_PAGE_CONTENT_CHARS` clause | `tests/test_cycle72_wrap_extensions.py:429-460` (`TestAC04_ConsistencyContextMigration._make_group` + `test_n4_fixture_emits_4_fences` + `test_per_page_content_bounded`) | Risk: silent regression of `_MAX_CONSISTENCY_WRAPPED_PAGE_CHARS` truncation cap.** | The lock-in fixture writes 4 pages of 50,000 chars each AND invokes `build_consistency_context(page_ids=pids, ...)`. But the production cap (`semantic.py:430` — `if len(content) > _MAX_CONSISTENCY_WRAPPED_PAGE_CHARS:`) is gated on `if auto_mode:` (L424). Manual mode (page_ids supplied) BYPASSES the cap entirely — the test exercises the wrap but NOT the truncation. Design-decision Condition 11 (line 109) literally requires "asserts each post-cap page length ≤ `MAX_CONSISTENCY_PAGE_CONTENT_CHARS`". The cycle-8 atomic test (`test_cycle8_consistency_caps.py:68-87`) does verify auto-mode truncation, but that's per-test-cap text only — not the AC09 lock-in. A regression that broke `_MAX_CONSISTENCY_WRAPPED_PAGE_CHARS` (e.g., reverting to `MAX_CONSISTENCY_PAGE_CONTENT_CHARS` so per-page wrapped content overshoots the budget) would NOT trip AC09 because manual mode skips it. | **Fix:** Add a third assertion to `TestAC04_ConsistencyContextMigration` running auto-mode (omit `page_ids`, set up shared-source frontmatter so the auto-grouper picks up the pages) with one page > `MAX_CONSISTENCY_PAGE_CONTENT_CHARS` and assert the truncation marker `[Truncated at {_MAX_CONSISTENCY_WRAPPED_PAGE_CHARS}` appears AND that the body length post-truncation is ≤ `_MAX_CONSISTENCY_WRAPPED_PAGE_CHARS + len(marker)`. Without this, Condition 11 is partial.

**M-2: AC04 design-decision Condition 5 explicitly resolved to "OPTION (a) modify in place" of `kb.config.MAX_CONSISTENCY_PAGE_CONTENT_CHARS = 4096 - _FENCE_OVERHEAD`; implementation chose option (b) (new `_MAX_CONSISTENCY_WRAPPED_PAGE_CHARS` constant in `semantic.py`) | `src/kb/lint/semantic.py:60` + `src/kb/config.py:475` + design-decision §Reconciled binding conditions cond. 5 (line 98) | Risk: deviation from binding gate condition without re-approval.** | Condition 5 says: "Modify `src/kb/config.py` `MAX_CONSISTENCY_PAGE_CONTENT_CHARS = 4096 - _FENCE_OVERHEAD` (option a). DeepSeek R1 already flagged this — confirming. | **Fix:** Either (a) re-confirm with the design-decision owner that option (b) is acceptable substitute (deviation from binding condition), document the swap in the cycle-72 design-decision addendum, AND update the cycle-22-L5 invariant; or (b) restructure imports (e.g., move `_FENCE_OVERHEAD` to a tiny leaf module like `kb.utils.fence_const`) to enable option (a). Either resolution is fine; what's NOT fine is shipping a binding-condition deviation without an addendum.
