# Cycle 61 — Threat model

**Surface scope:** AC1-AC13 (production code). AC14-AC21 are test/doc only — out of scope for STRIDE.

## Analysis

Cycle 61 modifies four trust boundaries / I/O surfaces:

1. **Subprocess invocation** (AC1-AC5, already in `d7a98b7`): `codex exec --json --ephemeral --sandbox read-only --skip-git-repo-check`. Audited at `src/kb/utils/cli_backend.py:64-107` and `src/kb/config.py:192-211`. The argv shape is fully constant except for the trailing `--model <name>` that `_build_cmd` appends. Model name is filtered through `_MODEL_RE = re.compile(r"^[A-Za-z0-9._:/-]*$")` (cli_backend.py:40) BEFORE `_build_cmd` returns; an invalid name raises `LLMError(kind="invalid_request")`. The empty-string anchored regex (note `*` not `+`) accepts an empty model name and the trailing append is gated on `model` truthiness, so empty == omit. JSONL parser at `_postprocess_stdout` (cli_backend.py:89-107): iterates `splitlines()` of `stdout_text`, calls `json.loads(line)` per line. Stdout is hard-capped to `MAX_CLI_STDOUT_BYTES = 2_000_000` BEFORE decoding (cli_backend.py:225) and BEFORE `_postprocess_stdout` runs — so the JSONL loop is bounded at ~2 MB regardless of how chatty the codex subprocess is. Each `json.loads(line)` runs on at most 2 MB and returns when the line is invalid (the `JSONDecodeError` `continue` is critical: malformed lines are silently dropped without raising). Windows path: `_backend_executable` returns `"codex.cmd"` literal — `shutil.which("codex.cmd")` is the resolution mechanism, which respects `PATHEXT` and the standard `PATH` lookup; we do NOT pass the resolved path to `subprocess.run`, we pass the basename. This means `subprocess.run` resolves it again with `shell=False`. The `env` is scrubbed via `_scrub_env` (cli_backend.py:110-125) to an allowlist (`CLI_SAFE_ENV_KEYS` ∪ `CLI_BACKEND_ENV_INJECT["codex"] = ("OPENAI_API_KEY",)`).

2. **Allowlist file load** (AC6-AC8, new `.data/lint_allowlist.json`): The current state at HEAD has `DUPLICATE_SLUG_ALLOWLIST: frozenset[frozenset[str]]` hardcoded at `src/kb/config.py:690-696`. After cycle 61, a runtime loader replaces the hardcoded source. The path is constructed under `PROJECT_ROOT / ".data" / "lint_allowlist.json"` (mirrors `FEEDBACK_PATH`, `VERDICTS_PATH` patterns at config.py:178-180) — `PROJECT_ROOT` itself is heuristic + walk-up + `KB_PROJECT_ROOT` env override. The consumer is `_is_allowlisted_pair` at `src/kb/lint/checks/duplicate_slug.py:59-61` (membership check on a `frozenset[frozenset[str]]`). Failure-open: per AC6, the loader MUST NOT raise — file-missing returns the in-code default; schema-mismatch logs WARNING and returns the in-code default.

3. **Env-var feature flag** (AC9-AC11, new `KB_DISABLE_VECTORS`): added to `src/kb/config.py` near other env-var booleans, read via `kb.config.KB_DISABLE_VECTORS` attribute lookup at call time (per cycle-18 L1 snapshot-binding hazard — design doc Risk row). Consumed in `src/kb/query/hybrid.py::hybrid_search` (currently at line 54). When True, short-circuits to BM25-only via the design's "top-of-function early return" path (design Q4 default).

4. **MCP tool `kb_rebuild_indexes`** (AC12-AC13): wraps `kb.compile.compiler.rebuild_indexes` (`src/kb/compile/compiler.py:642-814`), which is THE most destructive operation in the codebase — unlinks `HASH_MANIFEST`, the vector DB, and clears LRU caches. The wrapper validates `wiki_dir` via `_validate_health_wiki_dir` (`src/kb/mcp/health.py:18-19` → `_validate_wiki_dir` at `src/kb/mcp/app.py:121-144`, which performs a dual-anchor check: literal `is_absolute` + resolved `is_relative_to(PROJECT_ROOT.resolve())`). The underlying `rebuild_indexes` ALSO performs a dual-anchor check via `_validate_path_under_project_root` at compiler.py:615-639. So `wiki_dir` is path-validated TWICE — once at MCP boundary, once at library boundary — both checks raise / return error before any unlink. The `hash_manifest` and `vector_db` keyword overrides in `rebuild_indexes` are NOT exposed by the MCP wrapper per AC12 ("thin wrapper over `rebuild_indexes(wiki_dir=...)`") — only `wiki_dir` crosses the MCP boundary. Same-class peers all routed through `_validate_health_wiki_dir`: `kb_lint`, `kb_evolve`, `kb_graph_viz`, `kb_verdict_trends`, `kb_detect_drift` (and `kb_stats`, `kb_compile_scan`, `kb_reliability_map` per design Q5).

The audit trail is already wired: `rebuild_indexes` appends one `rebuild-indexes` line to `<wiki_dir>/log.md` via `append_wiki_log` (compiler.py:803-812). The wiki_log writer escapes pipe / newline / tab / leading markdown-prefix chars (`utils/wiki_log.py:91-97`) — so the audit line itself is not log-injection-vulnerable.

## Out-of-scope acknowledgements

- **T-OUT-1: model-name regex bypass via Unicode normalization.** `_MODEL_RE` runs on the raw string before normalization; an attacker-controlled config could pass a string that visually resembles `gpt-5.4` but is structurally different. Out of scope: the model name comes from `KB_CLI_MODEL_<TIER>` env var or `CLI_TOOL_MODELS` constant — both operator-controlled at single-user scale.
- **T-OUT-2: codex subprocess sandbox escape via the codex CLI itself.** We rely on codex's `--sandbox read-only` honoring its contract. Out of scope — that's an upstream-codex threat model, not ours; the four-flag invocation is verified at Step 14.
- **T-OUT-3: race between `kb_rebuild_indexes` and a parallel `kb_compile`.** `rebuild_indexes` already takes a `file_lock` on the manifest with 1s timeout (`compiler.py:719`); concurrent compile gets `error="lock busy"`. Out of scope: existing cycle-23+ design.
- **T-OUT-4: log.md corruption via embedded path containing markdown.** Audit message uses pipe-delimited fields with ZWSP escaping for leading `#`/`-`/`>`/`!`. Out of scope: covered by `utils/wiki_log.py:91-97`.

## Verdict

Cycle 61's surface delta is small and well-contained: subprocess hardening already in d7a98b7 (4 flags + JSONL parser + Windows shim), one runtime config-file load on a path under PROJECT_ROOT, one boolean env-var feature flag, and one new MCP wrapper around an existing dual-anchor-validated destructive helper. Material threats are T1 (codex argv injection — already mitigated by `_MODEL_RE`), T9 (path-traversal on `kb_rebuild_indexes` — already double-validated), T13 (env-var snapshot foot-gun — design explicitly calls it out), and T12 (missing MCP audit-tag — needs decision at Step 14). The other ten threats are either single-user-local accepted-risk or already mitigated by inherited code. Recommended mitigations are the three Step-14 verify rows: (1) extend the codex argv test to pin `--sandbox read-only` and `--skip-git-repo-check` positions, (2) confirm the AC10 implementation uses `kb.config.KB_DISABLE_VECTORS` attribute access (no module-top import), and (3) decide the `caller="mcp"` audit-tag question — implement or BACKLOG. Step 14 should verify T1, T2, T5, T7, T8, T9, T10, T12, T13 — the remaining four are inherited / out-of-scope acknowledgements.
